# 🧭 岗位研究工作台

一个用于整理 **岗位画像、薪酬来源、JD 原始资料、研究结论和历史趋势** 的轻量级岗位研究工具。

项目强调：

- 数据来源可追溯
- 少量可信数据优先于复杂自动抓取
- 原始资料与研究结论分离
- 人工判断长期保留
- JSON 可备份、可迁移
- 桌面端与手机端均可使用

> 当前稳定版：**v1.0.0**  
> 数据结构版本：**Schema 2.0**

## 主要功能

### 岗位档案

围绕单个岗位建立长期研究档案，包括：

- 岗位名称与分类
- 岗位摘要 / 简介
- 核心职责
- 任职要求
- 技能标签
- 最近更新时间

### 薪酬研究

按以下维度组织薪酬数据：

```text
岗位
└── 地区
    └── 经验段
        └── 多个数据来源
```

经验段固定为：

- 1–3 年
- 3–5 年
- 5 年以上

每条薪酬来源支持：

- 来源名称
- 来源类型
- 来源链接
- 可信度（A / B / C）
- 数据状态
- 样本日期
- 样本量
- 三档经验薪酬区间
- 备注

数据状态：

- 有效
- 待复核
- 过期
- 已废弃

### 薪资区间对比

不是简单计算一个“精确平均工资”，而是直接比较不同来源的：

- 最低值
- 最高值
- 区间重合程度
- 多来源共同区间

更适合用于岗位招聘研究和薪酬判断。

### JD 研究

保留 JD 原始资料，并与结构化研究结果分开。

支持记录：

- 岗位标题
- 来源
- 地区
- 日期
- 经验
- JD 原文

岗位画像则用于整理：

- 岗位简介
- 高频职责
- 常见要求
- 技能标签

### 研究结论

单独保存：

- 事实
- 人工判断
- 招聘建议
- 研究备忘

避免将原始数据、推测和结论混在一起。

### 历史趋势

可记录近年岗位薪资变化。

当前示例数据中部分历史值属于估算值，页面会与“当前研究”区分显示。

### 数据备份

支持：

- JSON 导出
- JSON 导入
- 浏览器本地快照
- 快照恢复 / 删除

当前数据保存在浏览器 `localStorage` 中。

## 数据存储

当前采用：

```text
HTML + JavaScript
        ↓
   localStorage
        ↓
     JSON 备份
```

这个结构适合个人或小团队的轻量研究工具。

如果未来数据规模明显增大，可以考虑：

```text
localStorage
    ↓
IndexedDB
    ↓
SQLite / 服务端数据库
```

目前不建议为了扩展功能过早增加复杂度。

## 数据原则

### 1. 来源优先

每条薪酬数据应尽可能保留：

```text
来源
日期
地区
经验
样本量
可信度
```

### 2. 正常数据不制造噪音

正常的“有效”状态弱化显示；只有：

- 待复核
- 过期
- 已废弃

需要明显提示。

### 3. 原始 JD 与结论分离

```text
原始 JD
   ↓
结构化整理
   ↓
人工研究结论
```

即使以后重新分析，也能回到原始资料。

### 4. 不追求伪精确

招聘市场更适合研究：

```text
8K–12K
10K–15K
```

而不是制造类似：

```text
¥10,438
```

这样的伪精确结果。

---

## 数据新鲜度

默认规则：

```text
≤ 180 天      有效
181–365 天   待复核
> 365 天      过期
```

系统不会自动删除旧数据。

旧数据仍然可能具有历史研究价值。

## 使用建议

第一次使用时：

1. 打开 `index.html`
2. 查看现有示例岗位
3. 新建自己的岗位
4. 添加薪酬来源
5. 保存 JD 原始资料
6. 填写研究结论
7. 定期导出 JSON
8. 重大修改前创建本地快照

建议把 JSON 备份保存到浏览器以外的位置。

---

## 浏览器数据说明

页面数据默认保存在当前浏览器的 `localStorage`。

因此：

- 清理浏览器站点数据可能造成数据丢失
- 更换电脑不会自动同步
- 无痕模式不适合作为长期存储
- JSON 才是正式的外部备份方式

## 项目定位

这不是招聘网站爬虫，也不是复杂 HR SaaS。

项目更关注：

> **把少量可信的岗位资料整理成可复核、可比较、可长期积累的研究资产。**

AI 更适合作为后续的研究辅助工具，而不是承担高成本、高维护的数据抓取基础设施。
